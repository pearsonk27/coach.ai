## Goal
Author the canonical Zod schema (`shared-types/timeline.z.ts`): `Beat`, `WorkoutRun`,
`WorkoutPhase`, `PhaseExercise`, catalog enums, `MusicRef`, and `PlanSlot.params`. Mirror into
Pydantic v2 in `apps/api`. Add a **drift snapshot test** (I3) so the two can't diverge.
Links: design §2 D3, §4, §6.

## Contract
- `Beat` union: `phase-intro | prep | work | rest | cooldown-hold`, each `{id, kind, durationMs}`,
   `work` carries `exerciseRef`, `cue?`, `round?`.
- `WorkoutRun { id, template, startedAtMs, endedAtMs?, durationMs, status, source, beats }`.
- `PlanSlot.params { work_scale?, rest_scale?, rounds_mult?, target_rpe_focus? }`.
- `MusicRef { provider, playlist_ref?, volume?, start_on? }`.

## Acceptance criteria
- [ ] `z.infer` types compile on all platforms (web/api/mobile import them).
- [ ] A CI "contract snapshot" test fails when TS and Pydantic diverge (mutate one side to prove it).
- [ ] `shared-types/CONTEXT.md` explains the contract + how to add a field without drift.

## Tests required
- `contract.drift.test.ts` — round-trips a fixture `workout_run` through both sides and asserts
   equality.
- A mutation check proving the test catches a deliberate divergence.

## Verification
Full pipeline + `just check-contract`. STOP-A applies: it **creates the public contract** —
prepare a STOP report (what shipped, why A, the risk = downstream coupling) for human sign-off
before merge.
