## Intent
Music plays **throughout a run** on the Class Display. MVP path = **oEmbed of the user's public
SoundCloud playlist** — no OAuth, no secret (D7/D8). The player **plugs into T-42's shared audio
graph** so cues can **duck** it (D10).

## Scope
- [ ] `GET /music/resolve { ref | playlistId }` → `{ provider, embedUrl, volume, startOn, loop }`
   (server resolves the user's `playlist.playlist_ref` to a public oEmbed URL).
- [ ] `<MusicPlayer ref|playlistId autoplayAt volume loop muted>` in `packages/ui`; it mounts the
   SoundCloud player and **routes it through the `useAudioGraph().musicGain` node** provided by T-42,
    so `duck()` (the countdown / bell / buzzer) lowers *its* volume temporarily.
- [ ] Mute persists per browser; graceful no-op when no playlist / blocked.

## Acceptance
A run with a user playlist renders the embed, fires at `start_on` (≈ run start) at stored `volume`,
loops, and is **duckable** via T-42's `duck()`; a run with **no** playlist plays silence (no crash;
cues still work via the graph). API contract covers `MusicRef` / `MusicResolveResponse`. Docs:
§2.8/§2.9/§5/§6.

## STOPs / HALTS
- **STOP-D (minor):** the embed/SDK dependency — prefer the native SoundCloud oEmbed player, avoid a
   bespoke SDK. No secret in MVP ⇒ no STOP-E yet (F-08 introduces it).
- Depends on **T-42** for `musicGain`/`duck()`.

## Definition of Done
`just` gate green; contract updated + drift test green; docs updated; e2e uses a **mock** embed + a
**ducking test** (cue → player volume drops → restores).

## Notes
SoundCloud oEmbed (`/oembed?format=json&url=…`) embeds any public URL with no token. OAuth to
auto-list the user's *created* playlists is F-08 (STOP-E/D).
