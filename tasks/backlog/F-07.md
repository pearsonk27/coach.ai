## Goal
A **pure** engine `evaluate(target: template|plan) → findings []` implementing the user's example
best-practice rules over the flattened `beats` + catalog. Expose via API and ship a reusable
agent skill to run it. This is the backbone for "better workouts" (F-04 consumes it).
Links: design §8 "Eval criteria", §6.

## Contract
- `findings[]: { severity: 'info'|'warn'|'fail', rule, target, detail, suggestion }`.
- Rules (seed defaults, tunable later):
   - **Equipment-change pacing:** consecutive exercises requiring different equipment → assert the
     gap ≥ `EQUIP_CHANGE_SECONDS` (default 30); else `warn`.
   - **Over-targeting:** per-session exposure per `muscle_group` > `GROUP_EXPOSURE_CAP`; else
     `warn`.
   - **Under-targeting (plan-level):** across a `workout_plan` cycle, target groups under-worked,
     or a week with no recovery slot; else `warn`/`fail`.
- API: `GET /templates/{slug}/evaluate`, `GET /plans/{slug}/evaluate` → findings JSON.
- Skill: `packages/agent-skills/evaluate-workout.md` (objective, inputs, the same rules, checks).

## Acceptance criteria
- [ ] On `hiit-full-body-30`: no equipment-change `warn` if every transition has ≥30 s rest;
   a deliberate 10 s rest between two different-equipment exercises **does** `warn`.
- [ ] On `fullbody-periodized`: no "week with no recovery slot" finding.
- [ ] Output is pure JSON the agent skill + `improve-workout` (F-04) can consume.

## Tests required
- Pure-function table tests for each rule (pos/neg fixtures).
- Skill: a smoke test that the skill runs over both seeds.
