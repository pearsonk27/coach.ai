## Intent
Add the audio-cue layer the user asked for: a **countdown in the last 10 s** of a work interval, an
**exercise-done bell** on work→rest, and a **workout-end buzzer** — and **duck the SoundCloud playlist**
while a cue sounds. Generated with Web Audio (no assets, no network, muteable). This task also **owns
the shared Audio graph** so T-43's player plugs into it.

## Scope
- [ ] **`useAudioGraph` (T-42 owns it):** one `AudioContext` + master `GainNode`; routes the
    SoundCloud `MusicPlayer` through `musicGain` and generated cues through `cuesGain`. Exposes
   `duck(level, durationMs, rampMs)`.
- [ ] Cue generator (Web Audio, muted-safe): `interval-count`, `exercise-done` (bell),
    `workout-complete` (buzzer), plus `work→rest`/`rest→work` ticks.
- [ ] **Countdown:** ticks every second during the **last 10 s** of every work interval; 5→1
    *emphasized* (higher/longer pitch).
- [ ] **Bell** at the end of each work interval (work→rest). **Buzzer** at run end (after final
    phase).
- [ ] **Ducking:** any cue fires `duck()` → default `duckLevel=0.3`, `durationMs≈1200`, ramp≈150 ms;
    a countdown **holds** the music ducked until the interval completes, then restores.
- [ ] **Global mute** silences cues + music; mute state persists per browser. **Graceful no-op**
    (no crash) if `AudioContext` is unavailable / muted / music absent.

## Acceptance
With a run running + music mocked: at `t=` the last 10 s of a work interval, the clock emits
`interval-count×10`; on work→rest a bell; at run end a buzzer; on every fire the `musicGain`
drops to ~30% for ~1.2 s then restores; global mute silences everything; no crash with no music.
Spec §2.9 / D10. Docs updated.

## STOPs / HALTS
- No new external dependency (Web Audio is native) ⇒ **no STOP-D**. No secret. Graceful no-op
   behavior is the key acceptance.

## Definition of Done
`just` gate green; cue + duck unit tests (use a mocked `AudioContext` / fake clock); docs updated;
**graceful no-op** verified; contract unaffected (audio is client-behaviour).
