## Intent
Upgrade T-33/T-43 from "paste a public URL" to **auto-pull the user's created SoundCloud
playlists** (including ones not manually shared), with a clean connect flow.

## Scope
- [ ] `POST /me/soundcloud/authorize | /callback` (OAuth 2.1 + PKCE, ~1h tokens, single-use
   refresh → server-held `refresh_token_ref` + rotation).
- [ ] A provider-agnostic connector: today SoundCloud, tomorrow others.
- [ ] "pick which of my playlists is my default" (lifts the one-to-one limit for real).

## Acceptance
pytest: token exchange + refresh + listing (with a **mocked** SoundCloud client); user selects a
default; the selected playlist flows through T-43. Migration + docs.

## STOPs / HALTS
- **STOP-E (new secret):** `SOUNDCLOUD_CLIENT_ID`/`SECRET`/redirect allow-list. **STOP-D:** the
   connector dependency. **STOP-A:** new OAuth surface.
- The MVP stays **public-oEmbed, no secret**; OAuth is an opt-in upgrade and must not break it.

## Definition of Done
`just` gate green; contract updated + drift test green; docs updated (note the new secret). No
secrets in repos (only in `.env` / secret manager).

## Notes
SoundCloud API: `api.soundcloud.com`, auth `secure.soundcloud.com`, OAuth 2.1+PKCE. Prefer a
small, pinned connector; keep it behind D7's `provider` abstraction.
