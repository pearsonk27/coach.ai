## Goal
T-10 (installing pydantic to run the migration) surfaced a **latent T-01 bug**: the Pydantic
mirror `app/contracts/schema.py` **cannot be imported** under pydantic 2.13. Fix it so the mirror
is importable, the OpenAPI schemas (T-30) can be built, and the I3 Pydantic-drift check has a
usable mirror. This is a T-01 closure task (contract artifacts), owned by the same author as T-01.

## Bug (reproducible)
`uv run python -c "import app.contracts"` fails:
```
pydantic.errors.PydanticUserError: Model 'PhaseIntroBeat' needs field 'kind' to be of type `Literal`
```
Two defects in `apps/api/app/contracts/schema.py`:
1. `Beat` uses `Annotated[Union[PhaseIntroBeat, PrepBeat, WorkBeat, RestBeat, CoolDownHoldBeat],
   Field(discriminator="kind")]` — `Field(discriminator=...)` is **not** the pydantic v2 API; the
   correct form is `Annotated[Union[...], Discriminator("kind")]` (import `Discriminator` from
   `pydantic`).
2. Each beat choice declares `kind: str = "phase-intro"` (a plain `str`) — a discriminated union
   requires the `kind` field to be `Literal`: `kind: Literal["phase-intro"] = "phase-intro"` (and
   `"prep"` / `"work"` / `"rest"` / `"cooldown-hold"` respectively).

## Why it is latent (not currently red)
Nothing in the committed pipeline imports the mirror: `just check-contract` introspects
`contract.fields.json` (a snapshot), not the Python classes; `just gates`/`pytest` skip the mirror.
So the bug sits dormant. It lights up the moment **T-30** builds the OpenAPI router (imports the
models) or **T-99**'s I3 py-drift actually compares the Pydantic mirror to the snapshot — both
`ready`/soon, so fix this **before** they start importing the mirror.
