## Schema (must match §4 exactly — these are the 16 tables T-10 owns)
catalog: `equipment`, `muscle_group`, `exercise`, `exercise_muscle_group` (join, composite PK,
`is_primary`), `exercise_equipment` (join, composite PK).
composition: `workout_template`, `workout_phase` (UNIQUE(template_id,position); CHECK
rounds≥1 / rest≥0 / prep≥0), `phase_exercise` (UNIQUE(phase_id,position); CHECK work_seconds>0;
exercise FK ON DELETE RESTRICT).
regiment: `workout_plan`, `plan_week` (UNIQUE(plan_id,week_index)), `plan_slot`
(CHECK rest⟺template_slug null).
account/playlist: `user` (quoted), `playlist` (user_id UNIQUE → one-to-one; CHECK volume∈[0,1]).
runs/feedback: `workout_run` (beats JSONB NOT NULL; owner_user_id/playlist_id SET NULL;
plan_slot_id plain optional UUID no FK), `user_preferences` (user_id PK; TEXT[] arrays),
`workout_feedback` (skipped TEXT[]; FK run ON DELETE CASCADE).

Key structural decisions (all from §4; see handoff STOP-S list):
- UUID PKs defaulting to `gen_random_uuid()` (Postgres 13+ builtin).
- JSONB columns: `exercise.cues`, `workout_template.music`, `workout_plan.cadence`,
   `plan_slot.params`, `workout_run.beats`/`music`.
- TEXT[] columns: `user_preferences.{target,avoid_muscle_groups,equipment_slugs}`,
   `workout_feedback.skipped`.
- `structure` / `phase_type` / `kind` are **TEXT** (structure is a *tag*, D5/I7 — not DB-constrained).

### Design decisions (ratified by human)
1. `user_preferences` PK = `user_id` (true 1:1 via PK->FK) — **APPROVED**.
2. Textual enums (`structure`, `phase_type`, run status, `cadence`, slot `kind`) are `TEXT`+`CHECK`
    — **APPROVED**.
3. UUID PKs default to **`uuidv7()`** (PG18+ core; time-ordered, low fragmentation) instead of
    `gen_random_uuid()` — **APPROVED**. Live-verified on PG18: 100,000/100,000 `uuidv7()` pairs are
   monotonic; ids carry a 48-bit wall-clock prefix (`01a087d8-....`). `uuid_generate_v7()` (the old
    pgcrypto name) is NOT resolvable on this server, so `uuidv7()` is the correct call.
4. `workout_run.plan_slot_id` = plain optional UUID, **no FK** — **APPROVED**.
5. `workout_template.created_by` = plain nullable UUID, **no user FK** (account is T-33) — **APPROVED**.
6. `user_preferences.{target,avoid}_muscle_groups` + `workout_feedback.skipped` are `TEXT[]` —
    **APPROVED**. Rationale: these hold a **flat set of string slugs** (no nesting, no per-element
    properties, no heterogeneity), where Postgres array operators (`@>`, `&&`, `= ANY`) express the
    "does this set contain X?" queries natively and are GIN-indexable. `JSONB` is reserved for the
    genuinely structured columns — `music` (object), `beats` (heterogeneous beat list), `cadence`
    (object), `params`/`cues` (free-form bags). Rule: **flat string-set -> TEXT[]; nested/object ->
    JSONB.**
7. **`user.email` is UNIQUE** — **APPROVED**. Added `uq_user_email`. Live-verified: a duplicate
   `INSERT` is rejected (`duplicate key value violates unique constraint "uq_user_email"`).

### Discovered issues + recommendations (NOT fixed here — outside T-10 surface, per I3 / golden rule)
**F-1 — T-01 contract mirror fails to import under pydantic 2.13.** Installing pydantic (a T-10 action)
exposed a latent T-01 bug: `from app.contracts import ...` raises
`PydanticUserError: Model 'PhaseIntroBeat' needs field 'kind' to be of type Literal`. The discriminated
union in `app/contracts/schema.py` uses a `kind` discriminator but the choices' `kind` fields are not
declared as `Literal` (and the union is not wrapped in `Annotated[..., Discriminator('kind')]`).
T-10 is unaffected (its schema/migration import chain is self-contained; `app.contracts` is never in
`sys.modules`; `just check-contract` still PASSES because its pydantic introspection is skip-guarded
until STOP-D).
**Recommendation:** open a small follow-up (suggested **T-01b**, or fold into T-31) to tag each beat
choice's `kind` as `kind: Literal["work"]`/etc. and annotate
`Beat = Annotated[WorkBeat | RestBeat | PrepBeat | CoolDownHoldBeat | PhaseIntroBeat, Discriminator("kind")]`.
Land it *before* T-30/T-31 import the mirror.

**F-2 — Postgres driver (`psycopg`) is not yet a declared dependency (STOP-D).** It was installed into
the venv *only* to run the live round-trip (kept out of `pyproject.toml` to avoid an unsanctioned new
dependency). T-11 should formally declare `psycopg[binary]` (or system-libpq variant) and wire a
Testcontainers/`DATABASE_URL` CI job so the guarded live test runs in CI; `just gates`/`just test`
still pass without a DB (the test skip-guards). This is the same STOP-D sign-off deferred by T-01.
